Memory-Mapped Enhanced Text

Video-card spec — shadow Apple II memory as VGA-style text

Draft

Summary

Memory-Mapped Enhanced Text (MMET) lets application code treat ordinary Apple II RAM as a high-resolution text framebuffer. The host selects a mode; the video card shadows configured memory regions and renders each cell as a glyph with independent foreground and background colors.

From the programmer’s point of view the workflow is simple:

  1. Set mode — tell the card columns, rows, and (optionally) which Apple II addresses to watch.
  2. Write cells — store two-byte (character, attribute) pairs into shadowed RAM.
  3. Scroll — increment first_line by 1; rewrite only the newly exposed row.
  4. Display — the card rasterizes from its shadow copy every frame; the CPU never touches card VRAM directly.

MMET reuses the shadow-memory pattern already used by Second Sight, A2DVI, and the PPU tilemap model: bulk screen data flows over the 1 MHz bus into host RAM; the card snoops writes and keeps its own copy for rendering.

Two host interfaces reach the same hardware modes — see Direct access (memory map + card I/O) and COUT firmware (PR#n + control codes for BASIC, Pascal, and other existing text software).

Two ways in

PathWho uses itHow the screen is driven
Direct MMET New apps, ports, shells Host writes (char, attr) cells in shadow RAM; card API sets mode
COUT firmware BASIC, Pascal, legacy text tools PR#n then PRINT / WRITELN; firmware interprets bytes + control codes

Both paths rasterize through the same MMET engine and support the same mode table.

Cell format

Each screen cell occupies two consecutive bytes in host memory:

offset +0   character code   (8-bit, PC/VGA code page 437 by default)
offset +1   attribute byte   (VGA text attribute)

Attribute byte (IBM VGA / mode 03h compatible)

BitsFieldValues
3–0Foreground color16-color palette index
6–4Background color16-color palette index (bits 6–4; bit 7 shared)
7Blink / bright0 = bright fg; 1 = blink fg (or bg bit 3 on some hardware)

Cards SHOULD implement the standard 16-color VGA text palette. Font glyphs default to 9×16 pixels (mode 03h) for 80-column modes and 8×16 for 132-column modes unless the mode table specifies otherwise.

Memory layout

Enhanced text uses a linear framebuffer, not the Apple II interleaved text-page address scheme. Row r, column c: 

line   = (first_line + r) mod ring_lines
offset = line × pitch + c × 2
address = base + offset

ring_lines = length ÷ pitch

where:

base
24-bit host address of byte 0 of the shadowed region (physical line 0)
length
Size of the shadowed ring buffer in bytes (≥ pitch × rows)
ring_lines
length ÷ pitch — number of physical lines in the ring
first_line
Line index (0 … ring_lines − 1) of the physical line displayed as row 0
pitch
Bytes per scanline = columns × 2
visible size
pitch × rows bytes on screen; rows ≤ ring_lines

Do not use the native $0400 line-address table for MMET. Software that assumes interleaved 40-column layout must be rewritten or use a translation layer. MMET is intended for new code and ports of PC/VGA text applications.

Example: 80×25 at base $2000, first_line = 0

pitch = 160 bytes   rows = 25   ring_lines = 25   length = 4000
display row 0 → physical line 0 → $2000 .. $209F
display row 1 → physical line 1 → $20A0 .. $213F
...
display row 24 → physical line 24 → $3E80 .. $3F1F

Scrolling and first line

Moving thousands of bytes over the 1 MHz bus for every scroll is too slow. MMET follows the Videx Videoterm model: the card keeps a ring buffer in shadow memory and a first line index that says which physical line is displayed as row 0. Scrolling is a register change plus a single-line write — not a block copy.

Scroll up one line (standard terminal behavior):
1. first_line ← (first_line + 1) mod ring_lines — increment only; no multiply
2. Rewrite one line — display row rows − 1 — at physical line (first_line + rows − 1) mod ring_lines

Videx firmware uses a similar “first line on screen” pointer ($6F8+n); its CRTC start address (R12/R13) is a byte offset equivalent to first_line × pitch. MMET exposes a line index on the host API so scroll is a single increment (or one small immediate I/O write) — no multiply-by-pitch on the Apple II. The card converts to a byte offset internally when driving VGA/CRTC hardware.

Ring buffer sizing

Strategyring_lineslengthNotes
Minimum ring (recommended) rows pitch × rows Each scroll reuses the top physical line as the new bottom; no extra RAM
Extra history rows + k pitch × (rows + k) k spare lines for scrollback capture or double-buffer tricks

first_line MUST satisfy 0 ≤ first_line < ring_lines and rows ≤ ring_lines. When ring_lines = rows, incrementing first_line wraps modulo ring_lines.

Scroll-up walkthrough (80×25)

Before:  first_line = 0,   ring_lines = 25,  pitch = 160
         display row 0 → line 0 @ $2000,  row 24 → line 24 @ $3E80

Scroll:  first_line = 1     (INC + conditional wrap — one fast I/O write)
         display row 0 → line 1 @ $20A0
         display row 24 → line 0 @ $2000  (wrapped — stale; rewrite this)

Rewrite: fill 160 bytes @ $2000  (one line of char+attr pairs)
         ; host: line_addr = base + line × pitch  (one multiply for the write)

Scroll-down

Reverse scroll decrements the origin: first_line ← (first_line − 1) mod ring_lines, then rewrite display row 0 (physical line first_line). Same cost: one register update + one line write.

Horizontal scroll

first_line is vertical only. Character-column horizontal origin is a separate future parameter (first_column); it is not derived by adding small increments to a byte offset.

Apple II memory mapping

The card watches host writes (and optionally reads) to a configured address range and mirrors them into an internal text buffer used for rasterization. On the Apple IIgs, shadowing typically applies to banks $E0/$E1 when the corresponding video region is enabled in $C035.

Default mapping suggestions

Buffer size Suggested host region Notes
≤ 4 KB HGR page 1 $2000–$2FFF Fits 80×25; disable native HGR display
≤ 8 KB HGR pages 1+2 $2000–$5FFF Fits 80×43 (6,880 B) and 80×50 (8,000 B)
≤ 16 KB SHR lower half $2000–$5FFF main+aux Fits 132×25 with margin
≤ 32 KB Full SHR $2000–$9FFF Fits 132×60 (15,840 B)

Mappings are user-defined. A program may place the buffer anywhere in RAM that the card can shadow — the same flexibility described for PPU tilemaps in the card API. Defaults exist so simple programs need not configure addresses manually.

What the card must not map

  • Screen-hole regions used by firmware or peripherals (Videx-style control bytes at $478+ etc.) unless explicitly requested
  • Language-card or I/O space when shadow inhibit is clear
  • Regions smaller than the mode buffer

Direct access — card API

MMET extends the Second Sight-style command interface at $C0B0–$C0BF (IIgs slot 3 / card I/O window). Bulk configuration uses the existing DMA handshake (0x01 → 0x00); mode changes use the long-running pattern (0xA5 success / 0xA6 error).

SetMode — enter MMET

Extends the existing SetMode command. Emulation flag $04 = MMET mode (proposed; distinct from Apple II emu $00, VGA $01, PPU $02, GPU $03). 

Byte 0  command = SetMode ($03)
Byte 1  mode_id   (0x02–0x05, 0x109–0x10C, or 0xFF + user VGA table)
Byte 2  emu_flag  $04 = MMET

Effect:

  • Card switches output to enhanced-text rasterization.
  • Native Apple II video scanner output is bypassed (same as VGA modes).
  • Default geometry and memory map for mode_id are applied.

SetTextGeometry

Optional override of columns / rows when a fixed mode ID is not used (mode_id = 0xFF custom VGA table). Normal MMET software selects a mode ID from the tables above.

columns   uint16   80 or 132 (must match active mode family)
rows      uint16   1 .. rows_max
reserved  uint16   0

SetTextMemoryMap

Define the shadowed ring buffer. 24-bit address, IIgs bank included.

base_addr      uint24   Host address of ring line 0
pitch          uint16   Bytes per line (0 = columns × 2)
length         uint16   Ring size in bytes (0 = pitch × rows)
first_line     uint16   Physical line displayed as row 0 (0 .. ring_lines − 1)

first_line may be omitted on first setup (defaults to 0). Changing only first_line is the intended fast path for scroll; see Scrolling.

SetTextFirstLine

Immediate command (no DMA handshake) — optimized for scroll hot paths on a 1 MHz host. Updates which physical line is row 0. 

first_line   uint16   New line index (0 .. ring_lines − 1)
                       Wrap: (first_line + 1) mod ring_lines for scroll-up

Cards SHOULD apply the new origin before the next frame rasterization. Internally: byte_offset = first_line × pitch (card-side multiply for CRTC/VGA). Host software SHOULD follow with a single-line write to the newly exposed row rather than copying the whole screen.

GetTextFirstLine

Immediate read (or via GetMemoryMap): returns current first_line, ring_lines, base_addr, pitch, and length.

GetMemoryMap

Returns card capabilities and the active MMET mapping (same command family as PPU GetMemoryMap). Minimum fields:

  • Supported mode IDs bitmask
  • Maximum rows for 80-col and 132-col
  • Current base_addr, pitch, length, ring_lines, first_line, columns, rows
  • Shadow active (bool)

SetTextFont

Reuses existing SetTextFont ($0F): ROM font, alternate ROM, PC ANSI 8×16, or user font uploaded to card SRAM. Font glyphs are rasterized by the card; they do not live in the host MMET buffer.

Rendering model

  1. Host writes update shadow RAM on the card (one-way snoop, same as A2DVI).
  2. Each display refresh, the card walks rows lines beginning at physical line first_line, wrapping at ring_lines.
  3. For each cell, look up glyph bitmap + apply fg/bg from attribute byte.
  4. Composite into the VGA/HDMI frame; present via existing Present path.

The card SHOULD read from its shadow copy, not directly from host RAM at scan-out time, so the host can update the buffer during active display without bus contention. Double-buffering the shadow (swap at VBL) is optional but recommended for flicker-free updates.

Host software usage

Minimal bring-up (80×25)

1. GetStatus / GetMemoryMap — verify MMET + mode 0x03
2. SetMode(mode=0x03, flag=MMET)
   ; default map: $2000, pitch 160, 4000 bytes
3. ; optional: SetTextFont(PC ANSI)
4. ; write cells — e.g. store $41,$07 at $2000 for 'A' white-on-black
5. ; card displays immediately; no explicit Present required for text

132×43 VESA mode

1. SetMode(mode=0x10A, flag=MMET)
2. SetTextMemoryMap(base=$2000, pitch=264, length=11352, first_line=0)
3. Fill 132×43 × 2 bytes in the ring at $2000 ..

80×43 mode

1. SetMode(mode=0x04, flag=MMET)
2. SetTextMemoryMap(base=$2000, pitch=160, length=6880, first_line=0)
3. Fill 80×43 × 2 bytes in the ring at $2000 ..

80×50 mode

1. SetMode(mode=0x05, flag=MMET)
2. SetTextMemoryMap(base=$2000, pitch=160, length=8000, first_line=0)
3. Fill 80×50 × 2 bytes in the ring at $2000 ..

Scroll up (80×25 terminal)

; ring_lines = 25, pitch = 160, base = $2000
1. SetTextFirstLine(first_line + 1)   ; wrap at 25 — INC, no multiply
2. ; physical line to rewrite = (first_line + 24) mod 25
   ; line_addr = base + line × pitch   (one multiply for the line write)
   ; write 160 bytes at line_addr — blank or new prompt line
; Scroll register update: O(1) add; total bus traffic ~162 bytes not ~4000

COUT firmware — PR#n interface

Many existing programs never touch video memory directly. They activate a slot firmware with PR#n (or the equivalent DOS command) and emit characters through the COUT vector ($FDED on 6502, GS/OS tool chain on the IIgs). This path lets BASIC, Apple Pascal, and similar environments use MMET modes without knowing about shadow maps or card I/O registers.

The model follows 80-column cards such as the Videx Videoterm and enhanced-text firmware on cards like VidHD: the host sets cursor coordinates in well-known screen-hole locations, sends a byte stream to COUT, and firmware interprets control sequences and writes the internal MMET buffer.

Firmware owns the MMET ring buffer, mode selection, and first_line scroll logic. Application code sees only COUT, screen holes, and escape sequences — the same contract as classic 80-column firmware, extended to 43/50-row and 132-column modes with color.

Activation

  1. Card installed in slot s (typically slot 3 on //e and IIgs).
  2. 256-byte firmware image mapped at $Cs00 (and optionally $C800–$CFFF for extended routines).
  3. PR#s — sets output vector to the card’s COUT entry.
  4. IN#s — optional; keyboard input (may pass through to standard GETLN or a minimal line editor).
  5. Firmware calls the card MMET API internally to enter default mode (80×25, 0x03) and map its private text buffer.

A soft-switch or annunciator (Videx-style $C058/$C059) MAY gate whether the card or native Apple video is displayed; firmware sets this when PR# is active.

Screen holes

Cursor and mode state live in the Apple II text-page screen holes, offset by slot number s (same convention as Videx and Apple Mouse). Pascal, BASIC extensions, and some word processors read these directly.

RegisterAddressR/WDescription
CH $578 + s R/W Cursor column, 0 … columns − 1
CV $5F8 + s R/W Cursor row, 0 … rows − 1
ATTR $678 + s R/W Current VGA attribute byte for COUT (default $07 light gray on black)
FIRSTLINE $6F8 + s R/W Scroll origin (first_line line index); firmware updates on scroll
MODE $7F8 + s R/W Active MMET mode ID (e.g. $03, $04, $109)
FLAGS $778 + s R/W Bit 0: alt charset; bit 4: firmware busy; bit 7: escape parser active

Writing CH/CV moves the cursor; firmware does not require the host to compute cell addresses. Reading CH/CV reflects the firmware cursor after the last COUT operation.

COUT character handling

When COUT receives a byte:

ByteAction
$20–$7E, $80–$FF Printable: store (char, ATTR) at (CH, CV); advance CH; wrap or scroll at line end
$08Backspace: CH ← max(0, CH − 1)
$0DCarriage return: CH ← 0
$0ALine feed: CV ← CV + 1; scroll if CV ≥ rows
$07Bell (host beep or card speaker click)
$09Tab: advance CH to next multiple of 8 (or firmware tab stops)
$1BEscape: enter control-sequence parser (see below)

Scroll on line feed uses the same first_line ring algorithm as direct MMET: firmware increments FIRSTLINE, clears or rewrites the bottom row — no full-screen copy on the host.

Control sequences

Sequences begin with ESC ($1B). Firmware parses a small subset sufficient for mode selection, cursor motion, color, and screen clearing. Printable output from BASIC/Pascal often mixes plain text with these codes via CHR$().

Mode selection

ESC  M  mode_id

Examples:
  ESC M $03     → 80×25
  ESC M $04     → 80×43
  ESC M $05     → 80×50
  ESC M $109    → 132×25   (two-byte mode: ESC M $01 $09)

After a mode change, firmware re-inits the MMET buffer, resets CH/CV to 0, updates MODE screen hole, and clears the display (or preserves screen per FLAGS — default clear).

Cursor position (CSI)

ESC  [  row ; col  H     →  CV ← row−1, CH ← col−1  (1-based, ANSI-style)
ESC  [  H               →  home: CV ← 0, CH ← 0

Attributes and color

ESC  [  attr  m          →  ATTR ← attr (VGA attribute byte, 0–255)
ESC  [  0  m               →  reset ATTR to $07

A minimal ANSI SGR mapping (30–37 foreground, 40–47 background) MAY translate to VGA attribute bytes for software that already emits ANSI color codes.

Erase

ESC  [  2  J              →  clear entire screen, home cursor
ESC  [  K                  →  clear from cursor to end of line

Scroll region (optional)

ESC  [  r1 ; r2  r         →  set scroll region rows (firmware-only; for advanced TUIs)

BASIC example

10 PRINT CHR$(4);"PR#3"          : REM activate slot 3 firmware
20 PRINT CHR$(27);"M";CHR$(4);     : REM ESC M $04 → 80×43
30 PRINT CHR$(27);"[2J";           : REM clear screen
40 PRINT "Hello in 80 columns, 43 rows."
50 FOR I = 1 TO 43: PRINT I: NEXT   : REM scroll via normal PRINT/LF

Pascal / assembly

Pascal runtimes often write through COUT but track cursor via CH/CV screen holes. Assembly code may JSR COUT or call the slot firmware directly at $Cs00. Either way, firmware maintains the MMET buffer; the host never writes two-byte cells itself unless it opts into direct MMET later.

Card requirements

A card claiming MMET support MUST implement:

  • Write snoop (shadow) on a configurable 24-bit address range
  • SetMode with MMET emulation flag
  • At least one 80-column mode (80×25 minimum) and rasterization to VGA/HDMI output
  • Two-byte cell interpretation (char + attribute)
  • Linear pitch = columns × 2
  • first_line ring indexing with modulo wrap at ring_lines
  • SetTextFirstLine immediate command for scroll
  • COUT firmware at $Cs00 with screen holes and escape parser (for PR#n access)

SHOULD implement:

  • 80-column modes through 80×50 and 132-column modes through 132×60
  • SetTextGeometry only for custom (0xFF) VGA tables
  • GetMemoryMap / GetTextFirstLine
  • VBL wait / double-buffered shadow swap

Known compatible architectures (emulation targets):

  • Second Sight (VGA text mode 03h baseline)
  • A2DVI v4+ (shadow engine; may need firmware update)
  • Emulators with E0/E1 shadow and slot-card VRAM
